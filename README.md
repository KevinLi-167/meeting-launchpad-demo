# 会议终端一键入会系统（Meeting Launchpad · Demo）

基于 Go 语言标准库实现的**会议室终端入会自动化执行器**：到点自动唤起会议室电脑上的会议客户端，并带上会议号。

> 📌 **本仓库是脱敏示例版**：仓库内所有会议室名称、房间号、内网地址、会议号**全部是示例值**，与任何真实单位、真实会议室无关。
> 部署到自己的环境时，按 [配置文件](#配置文件configjson) 一节替换成实际值即可 —— **不需要改代码，也不需要重新编译**。

---

## 它解决什么问题

会议室电脑上装好了各种会议客户端，但"到点开会"这一步总要有人来做：提前到会议室、打开对应软件、输入会议号。

本系统把这一步交给会议室电脑自己完成：

- 提前把会议（类型 + 会议号 + 时间）录进系统
- 到点后，会议室电脑**自动唤起对应的会议客户端并带入会议号**
- 临时会议也能一键唤起 —— 人在会议室现场，不用再逐个字段填写

服务是**单个可执行文件、零外部依赖、零 AI**，只在局域网内可达。

## 功能特性

- **多终端支持**：一份源码编译出多个终端实例，每个实例有独立的会议室信息与默认会议号
- **多会议类型**：全时云会议、腾讯会议、Zoom、Microsoft Teams、小鱼易连，另有「自定义链接」兜底通道
- **定时触发**：支持指定时间自动启动会议客户端
- **一键快捷启动**：页面预设按钮自动填表 + 内联二次确认，面向"线下会议临时转线上"场景
- **并发队列**：多个会议按时间顺序排队执行，同分钟多个任务依次执行
- **持久化存储**：任务数据持久化到本地文件（`tasks.json`），关机重启不丢失
- **执行日志与最近一次执行**：已执行 / 错过任务记录到 `tasks_log.jsonl`；页面展示最近一次执行结果（`GET /api/last`）
- **运行中会议检测**：执行前检查客户端是否已在运行，支持「记录并放行 / 跳过 / 弹窗确认 / 不检测」四档策略
- **配置分层**：编译期注入默认值 + 同级 `config.json` 可选覆盖（**配置文件可以删除，程序照常运行**）
- **Web 管理界面**：可视化界面进行会议预约管理
- **REST API**：JSON 格式的 HTTP 接口，可被脚本或 AI 助手调用（见 [`skill/`](skill/)）
- **静默运行**：支持开机启动时静默运行，日志输出到文件

## 快速开始

### 编译

需要 Go 1.24 或更高版本。

```bash
# 编译单个实例
go build -o output/meeting_server.exe .
```

或使用提供的脚本，一次编译出 4 个终端实例：

```bat
build.bat
```

产物为 `output/MeetingLaunchpad_v2.1-demo-room1.exe` … `room4.exe`，并附带启停脚本 `StartOrStop_v2.1.ps1`。

### 运行

```bat
REM 启动第 1 个终端（控制台模式，端口 8080）
output\MeetingLaunchpad_v2.1-demo-room1.exe -room 1

REM 启动第 2 个终端，自定义端口
output\MeetingLaunchpad_v2.1-demo-room2.exe -room 2 -port 8081

REM 静默运行（无窗口，日志输出到文件）
output\MeetingLaunchpad_v2.1-demo-room1.exe -room 1 -silent
```

启动后浏览器访问 `http://127.0.0.1:8080`（或 `http://<本机IP>:8080`）。

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-room` | 终端编号，取值 1–99 | 1 |
| `-port` | HTTP 服务端口 | 8080 |
| `-silent` | 静默运行模式，日志输出到文件 | false |

### 配置优先级

```
命令行参数  >  同级 config.json  >  编译期注入值（-ldflags -X）  >  代码内置值
```

编译期注入的写法（`build.bat` 内部即用这种方式产出 4 个实例）：

```bash
go build -o output/app.exe -ldflags "-s -w -X main.BuildRoomNo=2 -X main.BuildPort=8080 -X main.BuildSilent=true" .
```

## 配置文件（config.json）

配置文件放在**可执行文件同级目录**，文件名固定为 `config.json`。

> ✅ **它是可选的** —— 删除后程序使用内置值正常运行。

仓库根目录的 [`config.example.json`](config.example.json) 是一份可直接照抄的模板：把它复制到 exe 同级目录、**改名为 `config.json`** 即生效。

常用字段：

| 字段 | 说明 |
|------|------|
| `room_no` / `room_number` / `room_name` | 终端编号 / 物理房间号 / 会议室名称 |
| `default_meeting_no` / `default_meeting_type` | 页面默认会议号与默认会议类型（下拉框以此为准） |
| `port` / `silent` | 端口 / 静默模式 |
| `presets` | 「一键快捷启动」按钮，最多 3 个 |
| `client_process_names` | 各会议类型的客户端进程名（运行中检测用，**只填真机确认过的**） |
| `client_running_action` | `warn`（默认）/ `skip` / `confirm` / `off` |
| `confirm_timeout_sec` | 确认弹窗等待秒数 |
| `start_time_input_mode` | `native`（默认）/ `text` |
| `hide_config_entry` | `true` 时页面不显示「修改默认配置」入口（默认 `false`） |

> 配置文件**只在服务启动时读取一次**，修改后需**重启服务**生效。
> 页面刻意不提供"在线编辑、立即生效"：服务本身无鉴权，开放在线编辑等于开放一个无鉴权的远程写配置入口。配置变更交给现场的人确认更稳妥。

## Web 界面

界面功能：

- 显示当前会议室信息与配置来源
- **一键快捷启动**（预设按钮，自动填表 + 二次确认）
- 添加会议预约（类型、会议号、时间等）
- 查看待执行会议队列
- **最近一次执行**：队列下方展示最近一次已执行的会议（类型 / 会议号 / 起止时间 / 结果），取自本机执行日志
- **取出到编辑区**：删除任务并把内容回填表单（变相实现"修改"）
- **使用说明**按钮：点击弹窗显示完整使用规则
- **修改默认配置**按钮：在终端本机打开 `config.json`（有网页二次确认；可用 `hide_config_entry` 隐藏该入口）

### 任务执行规则

| 规则 | 说明 |
|------|------|
| 定时执行 | 到开始时间后自动启动对应会议客户端 |
| 同分钟多任务 | 同一分钟内多个任务依次执行，不会跳过 |
| 持久化 | 任务保存到 `tasks.json`，重启不丢失 |
| 执行日志 | 已执行 / 错过任务记录到 `tasks_log.jsonl` |
| 重启恢复 | 过期 5 分钟内的任务自动补执行，超过则标记为已错过 |
| 手动删除 | 可手动删除队列中的待执行任务 |
| 防误触 | 同类型 + 同会议号 + 开始时间相差 ≤60 秒且尚未执行的任务，重复提交会被识别为 `409` |

## API 接口

### 添加会议

```bash
POST /api/meetings
Content-Type: application/json

{
  "meeting_no": "89339802",
  "meeting_type": "quanshi",
  "start_time": "2026-06-15T14:30:00+08:00",
  "end_time": "2026-06-15T15:30:00+08:00",
  "meeting_name": "项目评审会议",
  "applicant": "小李"
}
```

- 成功 → `201`，返回新建后的完整对象
- 重复 → `409`，返回 `{"error":"...","meeting":{...}}`，**不重复创建**

### 获取会议列表

```bash
GET /api/meetings
```

### 删除会议

```bash
DELETE /api/meetings?id=1234567890
# 成功 → 204（幂等：id 不存在也返回 204）
```

### 最近一次执行记录

```bash
GET /api/last
```

返回 `{"found":true,"entry":{...}}`；从未执行过任何任务时为 `{"found":false}`。

> ⚠️ **口径**：日志记录的是「任务已被触发（客户端被唤起）」，**不等同于「已确认入会」** —— 全时云等客户端唤起后仍需人工点"加入"。

### 配置文件信息（页面内部使用）

```bash
GET /api/config/info
```

返回 `{"path":"<配置文件绝对路径>","exists":true}`。仅用于页面「修改默认配置」的二次确认框**实时**显示目标文件路径，**不会打开任何窗口**。

### 打开配置文件（仅页面按钮调用）

```bash
POST /api/config/open
```

在**服务端本机**打开（不存在则先创建模板）配置文件，返回 `{"path":...,"created":...}`。该操作会弹出窗口，故页面侧有二次确认；不需要该入口可设 `hide_config_entry: true` 隐藏。

## 会议类型

| 类型 | 标识 | 启动地址 |
|------|------|----------|
| 全时云会议 | `quanshi` | `tang://` |
| 腾讯会议 | `tencent` | `wemeet://` |
| Zoom | `zoom` | `https://zoom.us/j/<号>` |
| Teams 会议 | `teams` | `msteams://` |
| 小鱼易连 | `xylink` | `xylink://joinMeeting?number=<号>` |
| 自定义链接 | `custom` | 原样直传，**只允许 http / https** |

会议号一律为**纯数字（4–32 位）**；含字母、横线或带参数的复杂链接请选 `custom` 原样粘贴。

> **为什么长难链接不做解析**：Teams 邀请链接、带 `%` 编码的登录跳转链接等，字段多、不固定、无公开文档，解析的维护成本超过收益 —— 一律走「自定义链接」通道原样直传，只做**长度上限 + 协议白名单**，不做结构解析。

## 持久化存储

| 文件 | 说明 | 写入模式 |
|------|------|----------|
| `tasks.json` | 待执行任务列表 | 覆写（与内存同步，临时文件 + 重命名，防断电损坏） |
| `tasks_log.jsonl` | 已执行 / 错过记录 | 追加（每行一个 JSON） |

两个文件都位于**可执行文件同级目录**（不随当前工作目录漂移）。

  }
]
```

## 静默运行与开机自启

### 静默运行

静默模式适合开机自启场景：程序不在控制台输出任何信息，日志写入同目录的 `YYYYMMDD_HHMMSS.log`（**每次启动/开机一个文件**）。

### 开机自启（推荐做法：启动文件夹放快捷方式）

服务需要在会议室电脑**开机（登录）后自动跑起来**，否则"到点自动入会"无从谈起。下面两种做法都依赖 Windows 自带机制，**不安装任何常驻软件**。**推荐做法 ①**。

#### ① 启动文件夹放快捷方式（推荐）

1. `Win + R` → 输入 `shell:startup` → 回车，打开当前用户的「启动」文件夹
   （即 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`）
2. 给 `StartOrStop_v2.1.ps1` 建一个**快捷方式**（目标指向 `powershell.exe`，参数带 `-File "<脚本绝对路径>"`），把快捷方式放进该文件夹
3. 下次**登录**后自动执行 —— 服务静默起好，浏览器直接可用

**优点**：简单、可视、易排错（打开启动文件夹就知道有没有设）。
**已知小瑕疵**：脚本被自动拉起时，屏幕会**短暂闪一下黑窗口再消失**（PowerShell 宿主窗口闪出即退）。属观感问题，不影响功能（改进方向见 [ROADMAP](ROADMAP.md) §2.13）。

#### ② 任务计划程序（备选，配置项更多）

| 项目 | 值 |
|------|-----|
| 程序或脚本 | `powershell.exe` |
| 添加参数 | `-WindowStyle Hidden -ExecutionPolicy Bypass -File "D:\MeetingLaunchpad\StartOrStop_v2.1.ps1"` |
| 起始于 | **留空**（脚本用 `$PSScriptRoot` 定位 exe，不依赖当前目录） |

> ⚠️ 「常规」里请选**「仅在用户登录时运行」**。若选「不管用户是否登录都要运行」，进程会运行在非交互会话中，**确认弹窗永远看不见**。

### 启停脚本

`StartOrStop_Server.ps1` 是幂等开关：**在跑就停，没跑就静默拉起**。
它用 `$PSScriptRoot`（脚本自身所在目录）定位 exe，因此要求**脚本与目标 exe 放在同一目录**，且该目录下只有一个 exe（多个时需在脚本顶部显式指定文件名）。

> `.ps1` 必须保存为 **UTF-8 with BOM**，否则中文会乱码。

## 部署建议

1. **用「启动文件夹放快捷方式」设置开机自启**（见上文）—— 简单、可视、易排错
2. 每个终端单独部署，使用不同端口
3. **放行防火墙端口** —— 见下节，这是最容易漏掉的一步
4. 定期清理日志文件，避免占用过多磁盘空间

### 放行防火墙端口（局域网访问的必要条件）

服务本身监听 `0.0.0.0`（所有网卡），但 **Windows 防火墙默认会拦掉局域网内其他设备的入站连接**。
漏掉这一步的典型症状是：**本机能打开页面，同事的电脑 / 手机打不开**。

**两种做法效果完全一样**，任选：

| 做法 | 操作 |
|------|------|
| 图形界面 | `Win + R` → `wf.msc` → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口 `8080` → 允许连接 → 勾选适用的网络配置文件 → 命名保存 |
| 命令行 | 以**管理员身份**运行下面的命令 |

```powershell
netsh advfirewall firewall add rule name="MeetingLaunchpad-8080" dir=in action=allow protocol=TCP localport=8080
```

- 命令方式**默认对所有网络配置文件（域 / 专用 / 公用）生效**，与图形界面里三个都勾选等效
- 端口不是 8080 时替换 `localport` 后的数字
- 查看 / 删除规则：

```powershell
netsh advfirewall firewall show   rule name="MeetingLaunchpad-8080"
netsh advfirewall firewall delete rule name="MeetingLaunchpad-8080"
```

### 验证

```powershell
netstat -ano | findstr :8080     # 期望看到 0.0.0.0:8080；若只有 127.0.0.1:8080 说明监听范围不对
```

然后在**另一台**电脑上访问 `http://<终端IP>:8080`。

> ⚠️ **代理干扰**：若测试机挂着 HTTP 代理（`http_proxy` / `https_proxy` 环境变量），用 `curl` 访问内网地址会返回 **502** 而不是超时 ——
> 那是代理拦截，不是服务故障。测试时加 `--noproxy '*'` 绕过代理：
>
> ```bash
> curl -s -m 5 -o /dev/null -w "%{http_code}\n" --noproxy '*' http://<终端IP>:8080/api/meetings
> ```

## 技术栈

- Go 1.24，仅使用**标准库**（`net/http`、`syscall`、`encoding/json` 等），无任何第三方依赖
- 前端为服务端内联的单页 HTML（无构建步骤、无外部 CDN）
- 唤起客户端：Windows `ShellExecuteW`，失败回退 `cmd /c start`

## 已知边界（不是缺陷，是物理前提）

- **唤起会议客户端必须在目标电脑本机执行** → 每台终端必须各有一个常驻进程
- **会议室电脑平时关机** → 需要外部定时开机（BIOS 定时等）作为链路起点；若电脑在会议时间之后才开机，该次任务失效。**这是当前唯一需要人工介入的环节**
- **服务单向、纯内网**，不在公网暴露 → 不引入 HTTPS / 证书体系
- **局域网可达性由两道门把守**：① 服务监听 `0.0.0.0`；② Windows 防火墙放行入站端口
- **只有与终端同内网的设备能访问** → 云端 AI、沙箱环境、4G / 外网一律不可达。这不是故障，是网络边界
- **办公网内部也可能互相隔离**（VLAN 划分、无线与有线分离、访客网络隔离）→ "这台电脑探测不到终端"**不代表终端不在线**
- **判断终端在不在，一律用 HTTP 探测，不要用 `ping`** —— 企业网常默认禁 ICMP
- **页面无法主动推送提醒**（Web Push 需要安全上下文，且页面不打开就没有脚本在运行）
- **运行中检测依赖进程名准确**：内置值 `TangMeeting.exe`（全时云）/ `WeMeetApp.exe`（腾讯会议）/ `Zoom.exe` / `ms-teams.exe`（Teams）/ `XYWinQT.exe`（小鱼易连）。**只记录进程名、不记录安装路径**（各机器安装位置不统一）。进程名写错会把"没开的会"误判为"已开"从而跳过执行 —— 未收录的类型一律视为"未运行"，即照常执行
- **非 Windows 平台功能会缩水**：`sys_other.go` 里进程检测、确认弹窗为空实现，配置引导改用 `xdg-open` / `open`。项目实际部署目标为 Windows

## 配合 AI 助手使用

[`skill/meeting-launchpad/`](skill/meeting-launchpad/) 是一份给 AI 助手（WorkBuddy、Claude 等）用的接口说明书：地址发现、连通性自检、接口清单与调用示例、错误码表、推荐工作流、能力边界。

把该目录整个复制到本机助手的能力目录（例如 `~/.workbuddy/skills/`）即可生效 —— 之后就可以用自然语言说"帮我往 3 号会议室排一个下午两点的会"。

> 前提是**运行 AI 的那台电脑与会议室终端在同一内网**。云端 AI、沙箱环境一律访问不到内网地址。
