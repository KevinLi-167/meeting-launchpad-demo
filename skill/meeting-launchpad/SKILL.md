# 会议终端一键入会系统 · 调用说明（**公开版**）

> 📌 本项目对外公开发布版：**文中所有会议室名称、地址、会议号与链接均为示例值**，与任何真实单位、真实会议室无关。
> 本目录的文件名固定为 `SKILL.md` —— 这是 AI 助手识别本技能的入口名，请不要改名。
> 部署到你自己的环境时，把本文档与同目录 `config.json` 里的示例值换成实际值即可。

## 这个服务是什么

会议室电脑上跑着一个小服务（单文件 exe，无外部依赖），它替人做一件事：

> **到点了，自动把会议室电脑上的会议客户端唤起来，并带上会议号。**

使用者不用记"几点开会、会议号是多少、要打开哪个软件"，只要提前把任务录进去即可。

- ⚠️ **本版只提供上面这几个示例号**，**不含任何真实会议室的默认号** → 用户只说"启动"而没给号时，**先问用户**（见下文「用户只说『启动』时怎么办」）。

> ⚠️ **部署到你自己的环境时，务必把上面这些换掉**：`config.json` 里的会议室名称、房间号、默认会议号、`candidates` 地址都按实际办公网填写。
>
> 🔴 **发布本 skill 到公开仓库前，别忘了同目录的 `config.json`** —— 正式使用过的 `config.json` 里会留着**真实办公网的 `candidates` 地址**，必须先把 `base_url` 清空、`candidates` 换成通用示例（如 `192.168.1.x`）再发布。**光改本文档不够。**

## 能力边界（务必先理解，否则会给用户错误承诺）

> ⛔ **本 skill 的动作对象是「远端会议室终端」，不是运行 AI 的这台电脑。**
> 全程**只做一件事：向目标终端的 `:8080` 发 HTTP 请求**。
> 🔴 **不要在本机启动服务、不要在本机唤起会议客户端、不要在本机"代替"那台电脑做事** ——「**启动第 3 会议室的全时云**」= 让**那台远端电脑**去唤起**它自己**的客户端，与运行 AI 的这台机器没有关系。
> ⚠️ **也不要在本机找安装目录、找 exe、翻快捷方式** —— 那些都在远端终端上；你需要的只是**它的 IP 和 8080 端口**。

| 能做 | 不能做 |
|---|---|
| 录入预约，到点唤起会议客户端 | ❌ **不能代替人点"加入会议"**（全时云等客户端仍需人工确认） |
| 立即唤起（`trigger_type: immediate`） | ❌ 不能远程开关机 —— 电脑是否在线取决于现场（定时开机 / 日常在线） |
| 查询队列、删除任务、查看最近一次执行情况 | ❌ 不能确认"人是否真的入会了"（只记录"触发过"） |
| 局域网内**能发起 HTTP 请求**的设备录入（电脑浏览器、快捷指令等） | ❌ 跨网段 / 云端 / 沙箱环境一律不可达 |
| — | ❌ **不改配置、不代为打开配置文件**：「修改默认配置」（`POST /api/config/open`）会在会议室电脑本机弹出记事本窗口，属**现场人工操作**，AI 不要替用户触发 |

## 运行环境要求（**先读这一条，否则会误报故障**）

本 skill 只是说明书，**能不能用取决于运行 AI 的那台设备处在哪个网络位置**，与目标服务无关。

| 运行环境 | 是否可用 | 原因 |
|---|---|---|
| 电脑端，与会议室终端同一局域网 | ✅ 可用 | 能直接访问内网 IP |
| 电脑端，通过 VPN 接入该内网 | ✅ 可用 | 同上 |
| **云端 / 网页版 AI**（推理在公网机房） | ❌ **不可用** | 请求从机房发出，不在办公网内 |
| **沙箱 / 隔离容器环境** | ❌ **不可用** | 没有访问本机所在网络的权限 |
| 手机端 App，连办公 WiFi 同一网段 | ⚠️ **通常不可用** | 手机端 AI 一般没有"发 HTTP 请求"的工具，读得到说明书也调不动接口 |
| 手机端 App，走 4G / 外网 | ❌ 不可用 | 网络不可达 |

**失败时的正确判断顺序**（**不要误报"服务挂了"**）：

1. **先看自己是不是在云端或沙箱里** —— 这两类环境**必然**失败，跟目标服务开没开机毫无关系
2. 再看设备与会议室终端是否**同一网段**（把本机 IP 与终端 IP 比一比）
3. 最后才怀疑"服务没启动 / 端口被防火墙挡住"

> ❌ **典型误判**：在云端或沙箱里 `ping` 或 `curl` 内网地址失败，就向用户汇报"会议室终端没开机"。实际上那个环境**根本到不了这个内网**，这个结论是无效的。
>
> ✅ 正确做法：直接告诉用户 —— **"当前环境访问不到该内网，请在能与会议室电脑同网的电脑上使用本 skill"**。
>
> 🔴 **办公网内部也可能是隔离的**：常见 VLAN / 网段划分、无线与有线分离、访客网络隔离 —— **有些电脑之间本来就不通**。「我这台探测不到会议室终端」**不代表终端不在线**，这是网络策略，**不是本服务的问题**，也不必改服务配置。正确做法：**换一台能通到会议室终端所在网段的电脑使用本 skill**（示例网段 `192.168.1.x`），或直接在会议室终端本机上操作。
>
> ⚠️ **判断终端在不在，一律用 HTTP 探测，不要用 `ping`** —— 企业网常默认禁 ICMP，「**ping 不通但 8080 能通**」是常见现象；反过来 ping 通也不代表服务在跑。

## 目标实例的版本可能不同（**先确认，再动手**）

本说明按 **v2.1** 的能力编写。会议室终端上跑的那个 exe 可能是**更早的版本**，而各版本提供的接口并不一致：

| 接口 | v2.0 | v2.1 |
|---|---|---|
| `GET` / `POST` / `DELETE` `/api/meetings` | ✅ | ✅ |
| `GET` `/api/last` | ❌ | ✅ |

⚠️ **连通性探测只能证明「在线」，不能证明「版本」** —— `GET /api/meetings` 返回 `200` 只说明服务活着，**看不出它是哪个版本、支持哪些接口**。

因此：

- 某个接口返回 **`404`** 时，**先怀疑版本差异**，不要立刻断定「路径写错」或「服务异常」
- **目前没有「查版本号」的接口**，所以只能靠**已知的部署记录**判断，或让用户到现场看服务页面的页脚 / 启动日志
- **建议**：部署时把各终端**统一到同一版本**，从根上减少这类判断成本

> 🔧 **已知缺口（尚未实现）**：计划新增一个返回实例版本号的 GET 接口 —— 返回内容除版本号外，**最好带上「支持哪些接口」的能力清单**（比一个版本字符串有用得多）。有了它，调用方就能**先查版本、再决定调用哪些接口**，而不是靠 `404` 反推。
> **在那之前，「探测到在线」≠「接口齐全」。**

## 部署侧准备：放行防火墙端口（管理员在会议室电脑上做一次）

**服务即使已经启动，默认也可能只有本机能访问** —— Windows 防火墙会拦掉局域网其他机器的入站连接。要让局域网访问，必须放行端口（这一步容易漏，表现出来就是"本机能开、同事打不开"）。

**以管理员身份**运行：

```powershell
netsh advfirewall firewall add rule name="MeetingLaunchpad-8080" dir=in action=allow protocol=TCP localport=8080
```

- 端口不是 8080 时替换 `localport` 后的数字（端口由 `config.json` 的 `port` 或启动参数 `-port` 决定）
- 删除规则：`netsh advfirewall firewall delete rule name="MeetingLaunchpad-8080"`

**验证两步：**

```powershell
netstat -ano | findstr :8080     # 期望看到 0.0.0.0:8080，若只有 127.0.0.1:8080 则监听范围不对
```

然后在**另一台**电脑上：

```bash
curl -s -m 5 -o /dev/null -w "%{http_code}\n" --noproxy '*' http://<终端IP>:8080/api/meetings
# 期望 200；连不上就是防火墙或网段问题
```

> 配置入口说明：页面右上角的「修改默认配置」按钮会在**会议室电脑本机弹出记事本**，若部署方不希望暴露该入口，可在 `config.json` 里设 `"hide_config_entry": true` 隐藏它（不影响手工编辑配置文件）。

## 第一步：确定服务地址（首次使用只做一次）

服务地址记在本 skill 目录下的 `config.json` 里，**不用每次问用户**：

```json
{
  "base_url": "",
  "port": 8080,
  "applicant": "",
  "candidates": ["192.168.1.50", "192.168.1.51", "192.168.1.52", "192.168.1.53", "192.168.1.54"]
}
```

- `base_url` 留空 = 还没定过；定好形如 `"http://192.168.1.50:8080"`
- `candidates` 是候选地址清单（**示例值，按实际办公网改**），用户可以随时增删改
- 📌 **`candidates` 里除了会议室终端，也可以放「测试环境」的地址** —— 例如某台自用电脑，用来先把链路跑通、验证接口。
  **程序不关心某个地址是不是「会议室终端」，只关心它上面有没有在跑本服务。**
- 🔴 **`applicant` 只填「人」的名字** —— 它是队列里「这条是谁录的」那一列，纯给人看的。**不要填设备名，更不要填 IP**（服务端另有一条 `client_ip` 自动记录来源设备）。取值规则见下文「申请人的填写规则」。

**流程：**

1. 读 `config.json`。`base_url` **非空** → 直接用，跳到"自检"。
2. `base_url` **为空** → **必须先探测候选地址，然后主动向用户提问，不要自己猜一个就用**。

   探测（`-m 2` 控制超时，5 个地址最多 10 秒）：

   ```bash
   for ip in 192.168.1.50 192.168.1.51 192.168.1.52 192.168.1.53 192.168.1.54; do
     code=$(curl -s -m 2 -o /dev/null -w "%{http_code}" --noproxy '*' "http://$ip:8080/api/meetings" 2>/dev/null)
     echo "$ip -> ${code:-无响应}"
   done
   ```

   > 必须带 `--noproxy '*'`，否则挂了代理的机器上会全部返回 502，看起来"五个地址都不通"。

3. **拿探测结果去问用户**，例如：

   > 我扫到 `192.168.1.50` 在跑本服务（另外 4 个没响应）。是用它吗？还是给我别的地址？

   - 探测到**唯一一个** 200 → 请用户确认，确认即写入 `base_url`
   - 探测到**多个** → 让用户选
   - **全部无响应** → 直接问用户要地址，并提示"确认那台会议室电脑是否开机、是否和你在同一网段"
   - 用户改主意 → **直接改 `config.json`**，随时可以改，不需要重新装 skill

4. 把确认后的地址**写回 `config.json` 的 `base_url`**，之后每次直接用。

> ⚠️ 探测用的是**内网地址**，只在办公网内可用；`127.0.0.1` 只在"你就坐在这台会议室电脑前"时才对。

**连通性自检**（每次开工前做一次，能一次性排除掉 90% 的问题）：

```bash
curl -s -m 5 -o /dev/null -w "%{http_code}\n" --noproxy '*' "$BASE/api/meetings"
# 期望 200      → 服务在线
# 502 / 403     → 请求被代理拦截了，见下方「代理」说明
# 超时 / 拒绝   → 服务没起、IP 错了、不在同一网段，或防火墙挡了
```

> ⚠️ **代理坑（办公电脑上极常见）**：本机若挂着 HTTP 代理（`http_proxy` / `https_proxy` 环境变量），内网地址会被送去代理，典型症状是**返回 502 而不是超时** —— 看起来像"服务挂了"，其实服务好着。
> **本文档所有 `curl` 命令都要带 `--noproxy '*'`**，绕过代理直连。不确定有没有代理时先看一眼：
>
> ```bash
> echo "$http_proxy $https_proxy"
> ```

## 接口清单

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/meetings` | 查询全部待执行 / 已执行的队列 |
| `POST` | `/api/meetings` | 新增一条预约（或立即执行） |
| `DELETE` | `/api/meetings?id=<id>` | 删除指定任务 |
| `GET` | `/api/last` | 最近一次执行记录（类型 / 会议号 / 时间 / 结果） |

**只使用上表列出的接口。** 服务内部还有一些**面向网页界面**的接口（例如会在会议室电脑本机弹出窗口的操作），**一律不要调用** —— 本 skill 是给远端/AI 用的读取与录入通道，不替代网页界面。若某件事网页能做而这里没有对应接口，让用户自己去开网页。

### 1. 查询队列

```bash
curl -s --noproxy '*' http://<IP>:8080/api/meetings
```

返回一个 JSON 数组，每项形如：

```json
[
  {
    "id": "1758961234567890123",
    "start_time": "2026-09-29T06:00:00Z",
    "end_time": "2026-09-29T07:00:00Z",
    "meeting_no": "89339802",
    "meeting_type": "quanshi",
    "meeting_name": "示例会议",
    "applicant": "小李",
    "status": "pending",
    "scheduled_time": "2026-09-28T09:00:00Z",
    "client_ip": "192.168.1.77",
    "trigger_type": "scheduled"
  }
]
```

字段含义：

| 字段 | 说明 |
|---|---|
| `id` | 任务唯一标识，删除时要用 |
| `start_time` | **计划执行时刻**（RFC3339，带时区），到点自动触发 |
| `end_time` | 结束时间，可选，**仅用于记录**，不影响实际结束 |
| `meeting_no` | 会议号（纯数字）；`meeting_type=custom` 时必为空 |
| `meeting_type` | `quanshi`（全时云）/ `tencent`（腾讯会议）/ `zoom` / `teams` / `xylink`（小鱼易连）/ `custom`（自定义链接） |
| `custom_url` | 仅 `custom` 类型有值 |
| `status` | `pending`（待执行）/ `running`（执行中）/ `completed` / `missed`（超窗未执行） |
| `scheduled_time` | **录入时刻**（谁在什么时候下的单） |
| `client_ip` | **发起者 IP**，自动记录，无需传参 —— 用于追溯"这条是谁录的" |
| `trigger_type` | `scheduled`（预约）/ `immediate`（立即执行） |

### 2. 新增预约

```bash
curl -s -X POST http://<IP>:8080/api/meetings \
  --noproxy '*' \
  -H 'Content-Type: application/json' \
  -d '{
        "meeting_type": "quanshi",
        "meeting_no": "89339802",
        "start_time": "2026-09-29T14:00:00+08:00",
        "end_time":   "2026-09-29T15:00:00+08:00",
        "meeting_name": "示例会议",
        "applicant": "小李"
      }'
```

**拿到的是链接而不是纯数字会议号时**，用 `custom` 类型原样直传：

```bash
curl -s -X POST http://<IP>:8080/api/meetings \
  --noproxy '*' \
  -H 'Content-Type: application/json' \
  -d '{
        "meeting_type": "custom",
        "custom_url": "https://meeting.example.com/j/1234567890",
        "start_time": "2026-09-29T14:00:00+08:00",
        "meeting_name": "示例会议",
        "applicant": "小李"
      }'
```

- 成功 → `201`，返回**新建后的完整对象**（含 `id`、`client_ip`）
- 重复 → `409`，返回 `{"error": "...", "meeting": <已存在的那条>}`，**不重复创建**

请求字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `meeting_type` | 否 | 留空则用终端上配的默认类型 |
| `meeting_no` | **是**（除 custom） | **纯数字，4–32 位**。含字母/横线/带参数的一律改用 `custom`。**用户没说会议号时怎么办，见下文「用户只说『启动』时怎么办」** |
| `custom_url` | **是**（custom 时） | 完整链接，**只允许 `http` / `https`** |
| `start_time` | **是** | RFC3339，例如 `2026-09-29T14:00:00+08:00`。**务必带时区偏移** |
| `end_time` | 否 | 同上格式，仅记录用 |
| `meeting_name` | 否 | ≤64 字 |
| `applicant` | 否 | ≤32 字。**取值规则见下文「申请人的填写规则」** |
| `trigger_type` | 否 | `scheduled`（默认）/ `immediate`（立即执行，不等时间） |

**立即执行**：把 `start_time` 设为当前时刻并带上 `"trigger_type": "immediate"`，服务会在下一次轮询（≤1 秒）内唤起客户端 —— 这也是网页上「一键快捷启动」按钮走的那条路。

### 用户只说「启动」时怎么办

用户说「**启动会议室的全时云**」「现在把会议室开起来」这类话时，**不要再问时间** —— 直接立即启动：

**这几种说法都算「只说启动」，都只免掉「问时间」，不免掉「问会议号」**：「启动会议室的全时云」「**启动全时云默认会议号**」「用默认号把会议室开起来」。

| 要素 | 取值 |
|---|---|
| `meeting_type` | 用户点名了就用（「全时云」→ `quanshi`）；没点名就留空，服务端会回落到该终端配的默认类型 |
| `meeting_no` | ⚠️ **本版不含真实会议号，必须问用户**，问法见下 |
| `start_time` | **当前时刻**，带时区偏移（`+08:00`） |
| `trigger_type` | `"immediate"` |

**会议号怎么定**：用户没说号时，**问一句，并把下面这一问一并问出去** ——

> 「这台终端上有没有配『**默认会议方式 / 默认会议号**』和『**一键快捷启动**』按钮？配了我就直接用它启动；没配请把会议号给我。」

- 用户确认**配了** → 用确认后的那个号启动
- 用户**不知道 / 没配** → 让用户报号，拿到再发，**不要凭猜**
- ⛔ **「启动」= 让远端那台会议室电脑去唤起它自己的客户端** —— **AI 不做任何本机动作**：不安装、不启动、不找目录、不翻快捷方式，只向那台终端的 `:8080` 发一个 `POST`。
- 📌 **「启动」不等于「入会」**：服务只把客户端唤起并带上号，全时云客户端起来后**仍需人工点"加入"**才真正进会。所以「先启动、再到客户端里改号」是可行路径

📌 **提交之后会发生什么（三条机制，决定了怎么回报）**

1. 🔴 **真正决定「何时唤起」的是 `start_time`，不是 `trigger_type`** —— 服务端按「`start_time` ≤ 当前时刻」判定到点（队列每秒扫一次），`trigger_type: immediate` 只是页面上和流水里的**标记**。所以两个字段都要填对：`immediate` 标记成「一键立即启动」，`start_time` 给当前时刻才真的立刻跑。
2. 🔴 **一次用户指令只发一个 `POST /api/meetings`** —— `immediate` 任务入队后约 1 秒就被置为「执行中」，**服务端的 60 秒重复保护对它基本不生效**，所以「再发一次确认一下」会**真的把客户端再唤起一次**。想确认结果就读 `GET /api/meetings` 或 `GET /api/last`，**不要重复提交**。
3. **成功码只代表「已入队」** —— `201` 意味着任务已持久化、即将被唤起（≤1 秒），**不代表客户端已经起来**。回报时说「**已提交，服务将在 1 秒内唤起客户端并带入会议号 `<号>`**」，别说「已启动完成」。之后可用 `GET /api/last` 看实际执行结果。

### 申请人的填写规则（**每次录入都要给一个**）

`applicant` 是队列里「**这条是谁录的**」那一列，**纯给人看的**。服务端另有一条**调用方看不到、也无法伪造**的 `client_ip`，自动记录发起设备 —— 所以**不要把 IP 写进 `applicant`**。

取值按下面顺序，**取到就用，不要为它打断用户**：

| 顺序 | 来源 | 说明 |
|---|---|---|
| ① | **用户本次明确给的昵称 / 姓名** | 例如「帮我用小张的名字排一下」→ `applicant: "小张"` |
| ② | **`config.json` 里记着的 `applicant`** | 之前问过、用户同意记住的**人名**（🔴 **设备名永不写入这里**） |
| ③ | **运行 AI 这台电脑的设备名** | 当天问过、用户没答时的兜底；**只用于本次录入，不回写 `config.json`**（取法见下） |

- **每天第一次录入时问一句**：例如「这条会议记谁的名字？」—— 给了就写进 `config.json` 的 `applicant`，**当天后续录入不再问**；第二天第一次录入再问一次
- 🔴 **用户没回答 / 说「随便」/ 不想记 → 不追问、不打断流程**，本次直接用第 ③ 条兜底。设备名**不写进 `config.json`** —— 否则下次会被当成"记住的人名"复用，让后面所有记录都挂着别人的设备名，反而造成误判
- **设备名怎么取**：取 **AI 实际运行那台机器**的设备名（**不是**会议室终端、也不是用户手机）
  - 优先读环境变量 `COMPUTERNAME` —— **不执行外部命令，不会触发沙箱/权限提示**
  - 取不到再用 `hostname` 命令
  - 🔴 **两者都取不到就留空**，绝不为此中断录入或反复尝试
  - **原样使用**：不做加工、不加后缀、不写成"某某的电脑"这类形式
- ⚠️ **任何情况下都不要因为缺 `applicant` 而拒绝或推迟录入** —— 它在服务端是**可选字段**，缺了任务照样能建
- 后台另有 `client_ip` 记录来源设备，**页面不会标注"这条是设备名兜底"** —— 不必向用户解释这个机制；用户事后想改成别的名字，按新名字录入即可
- 汇报结果时顺口带一句「申请人记的是 XXX」，让用户有机会纠正，比事后翻队列来找便宜

### 3. 删除任务

```bash
curl -s -X DELETE --noproxy '*' "http://<IP>:8080/api/meetings?id=<任务的id>"
# 成功 → 204（无响应体）
```

`id` 从查询接口拿。注意：**已执行完成的任务不在队列里**，删不掉（也不该删，那是留痕）。

> ⚠️ **实测补充（2026-09-29）**：删除**不存在的 `id` 同样返回 `204`**（幂等删除，不报错）。所以**不要只看返回码就断定"删掉了"** —— 删完请再 `GET /api/meetings` 看一眼目标是否真的不在队列里。

### 4. 最近一次执行记录

```bash
curl -s --noproxy '*' http://<IP>:8080/api/last
```

返回 `{"found":true,"entry":{...}}`。**从未执行过任何任务时 `found` 为 `false`** —— 这不是错误，如实告诉用户"还没有执行记录"即可。

`entry` 的字段与队列接口一致，其中 `result` 的取值：

| 取值 | 含义 |
|---|---|
| `success` | 客户端已被成功唤起 |
| `failed` | 唤起失败 |
| `missed` | 超窗未执行 |
| `skipped_running` | 因检测到客户端已在运行而跳过 |
| `cancelled_by_user` | 现场人工取消 |

⚠️ **口径必须向用户讲清楚**：这是「**触发记录**」，**不等于「已确认入会」**。全时云等客户端唤起后仍要人点"加入"，所以不要把 `success` 说成"入会成功了" —— 它只表示"客户端被成功唤起"。

### 时间怎么算、算完怎么报

终端上的公网时间不一定准。**所有时间由调用方算好再传**，不要依赖终端本地时间。

- **算**：把"X 分钟后"这类相对时间，按 **AI 实际录入那一刻的系统时间** 算 `t + X`
  （取时间用系统命令，不凭记忆推算）。
- **报**：录入成功后回报**绝对时刻**，并补一句相对偏移，例如"比你下单约晚 20 秒"；
  偏移偏大（超过约半分钟）时顺口提一句可改写为精确时刻。
- **要对齐就直接给绝对时刻**（如 `20:50`），AI 只做时区换算。

> 服务端按 1 秒轮询触发（**实测从计划时刻到实际唤起延迟约 1 秒**）。因此"会议比约定晚了几十秒"这类误差**几乎全部产生在「用户下单 → AI 录入」这一段**，不要归因于服务慢 —— 属不可控范围，如实报出即可，不必追求卡秒。

## 推荐工作流

**用户说"启动会议室的全时云"时**（没说会议号、也没说时间）：

1. **取服务地址**：同「第一步」，**不要猜地址**
2. **定会议号**：⚠️ **本版没有真实会议号，必须问用户**；问的时候顺带确认一句「这台终端有没有配『默认会议方式 / 默认会议号』与『一键快捷启动』按钮？」
3. **定类型**：用户说了就用（「全时云」→ `quanshi`），没说就留空
4. **定时间**：`start_time` = **当前时刻**（带 `+08:00`），`trigger_type` = `"immediate"`
5. **定申请人**：按上文「申请人的填写规则」取值
6. `POST /api/meetings` → `201` 即成功。**回报时说清**「已按 <会议号> 立即启动」

**用户说"帮我预约 X 点的会"时：**

1. **取服务地址**：读 `config.json` 的 `base_url`；为空则按"第一步"走一遍（探测候选 → 问用户 → 写回）。**不要猜地址。**
2. `GET /api/meetings` —— **先看有没有冲突**：同一时段是否已有任务
3. **定申请人**：按上文「申请人的填写规则」取值（用户本次给的 → `config.json` 里记住的人名 → 本机设备名兜底，**兜底值不回写配置**）
4. 组装时间：把用户说的"明天下午 2 点"换算成带时区的 RFC3339
5. `POST /api/meetings`
6. **看返回码**：
   - `201` → 成功，把 `start_time` 和 `id` 念给用户确认
   - `409` → **不要重试**，说明"已经有一条同样的任务了"，把返回里 `meeting` 的时间念给用户
   - `400` → 把 `error` 原文转给用户（通常是会议号格式或时间格式）
   - 超时/连不上 → 告诉用户终端可能没开机，或地址不对

**用户说"取消某个会"时：**

1. `GET /api/meetings` 找到目标（用会议名/会议号/时间比对）
2. **把匹配到的任务念一遍让用户确认**再删（删错了要重新录）
3. `DELETE /api/meetings?id=...`

## 错误码速查

| 状态码 | 含义 | 处理 |
|---|---|---|
| `200` | 查询成功 | — |
| `201` | 创建成功 | 回报 `id` 与时间 |
| `204` | 删除成功（**幂等**：`id` 不存在也返回 204） | 删完再 `GET /api/meetings` 确认目标已不在 |
| `400` | 参数不合法 | 把 `error` 原文给用户 |
| `404` | 路径不对，**或该实例版本较旧、没有这个接口** | 先按「目标实例的版本可能不同」确认版本，再检查是否少写了 `/api/...` |
| `405` | 方法不对 | 例如对 `/api/last` 用了 POST |
| `409` | **幂等命中，已存在同类任务** | **不要重试**，告知用户已存在 |
| 连不上 | 终端未开机 / 不在同网段 / 端口不对 | 让用户确认终端状态 |

## 需要提前告知使用者的五条限制

1. **没有账号与口令**（有意为之）。**任何能访问到该 IP 的设备都能读写队列**。所以请只在可信的办公内网里使用，不要把端口映射到公网。这也是立项时的取舍：会议室场景里加登录会拖慢"临时加会"这个最高频动作。
2. **唤起 ≠ 入会**。客户端被拉起后，全时云等仍需人工确认；本服务无法代劳。
3. **同一会议客户端同时只吃一个会议号**。若会议室里已经开着某个会议，再触发另一个会议，多数客户端不会自动切号（需要先关掉当前界面）。所以"运行中检测"策略默认只记录、不阻断。
4. **重复提交会被拦**：同类型 + 同会议号 + 开始时间相差 ≤60 秒且尚未执行的任务，第二次会得到 `409`。这是防误触设计，不是故障。
5. **只有会议号，没有密码**。各类客户端自带的入会口令（如小鱼易连的 `pwd`、Teams 的 `p`）**当前不支持** —— 数据里没有承载它的字段。遇到"需要密码才能进"的房间，得让用户到现场手输，或确认该房间是否真开了密码。

## 安全提醒（给调用方 / AI 助手）

- 本接口是**明文 HTTP**，且**无鉴权**。不要把它当成对外服务。
- **一律用参数化方式传值**，不要让会议号/URL 混入 shell 拼接；`custom_url` 只允许 http/https，服务端会挡掉 `file://` 之类的协议。
- 不要把 `client_ip` 当成鉴权依据 —— 它只是留痕。
